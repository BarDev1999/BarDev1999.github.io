Video-to-Report LLM Pipeline

In plain words

Long recorded sessions hold useful details that nobody has time to rewatch. This tool turns them into short, searchable written reports and checks what was said against real market data.

What it does

Takes a recording, even one without captions, and produces a structured written report.

Why it matters

An AI summary alone cannot be trusted on specifics, and long recordings can cut a summary off midway.

What it shows about me

Building dependable AI pipelines: splitting work into steps, handling model failures and checking AI output with plain code.

How it works

Choose a stage to see what it does and the reasoning behind it.

Intake

New recordings are picked up from an inbox or passed as a link. A normalizer resolves the URL and yt-dlp extracts the audio. Finished items are recorded so nothing is processed twice.

Why it is built this wayLinks arrive in many forms for the same recording. Normalizing them first makes duplicate detection reliable.
IMAPyt-dlpSQLite

Transcribe

Audio is transcribed with Whisper and Gemini, so the pipeline does not depend on captions being available. Transcripts are stored in full.

Why it is built this wayStoring the transcript separates the expensive step from the report. A report can be rebuilt from it without downloading the recording again.
WhisperGemini API

Two-stage prompts

The first stage produces a complete transcript with every detail. The second turns it into a structured report with fixed sections, one card per topic.

Why it is built this wayOne prompt asked to do both ran out of output tokens on long recordings and cut off silently. Separating the jobs gives each one the full budget.
Prompt engineering65K token output

Model fallback

Calls run through an ordered chain of models. When one fails or is unavailable the next takes over, and the run is logged.

Why it is built this wayA pipeline that runs unattended cannot depend on a single model being available.
Fallback chainRetries

Validate

A deterministic module computes indicators from market data for each ticker the report mentions and adds a validation table.

Why it is built this wayThe LLM reports what was said. Code checks the chart. Keeping these apart makes disagreement visible instead of hiding it.
yfinancePandasNumPy

Serve

Reports go to a searchable archive, a local dashboard, a Telegram summary and an MCP server with six tools. A separate application reads the report files read only.

Why it is built this wayPlain files are a simple contract between systems, and the reader maps tables by header words so a change in report layout does not break it.
MCPhttp.serverTelegram Bot API

Technical detail

Optional reading for engineers and hiring managers.

  • The web dashboard binds to 127.0.0.1 by default and is not reachable from the network.
  • Credentials stay in local configuration on my machine, and the project is in no public or shared repository.
  • Recordings, transcripts and reports are for personal use and are not republished.
  • This page uses invented examples only.

Split the job in two

Transcription and structuring are separate LLM calls, which solved silent truncation on recordings of an hour and a half or more.

Plan for model failure

An ordered fallback chain keeps unattended runs going and records which model produced what.

Deterministic checks beside the LLM

Market data validation is plain code that sits next to the generated text and is never blended into it.

Expose it to agents through MCP

Six tools cover processing, archive search, validation and per-ticker history, so an AI agent can use the archive directly.

  • The 23 recordings figure is measured from the pipeline's own archive, not estimated.
  • Saved transcripts allow reports to be regenerated, so a prompt change can be compared on the same input.
  • The downstream parser was written against every label found in the first 20 sessions, including an older report layout.
  • Every ticker in a report is checked against live market data rather than trusted from the transcript.

Scope, stated plainly

This is a personal productivity tool, and its reports are not investment advice. The market data checks test whether a statement is consistent with a chart, not whether a trade would work. I built it with AI coding agents: I defined the requirements and acceptance criteria, reviewed the results and decided what shipped.
